# Mahjong Scheduler — Supabase Setup & RLS Documentation

This guide provides instructions for setting up the `usage_events` database table in Supabase, enabling Row Level Security (RLS), and configuring your application files (`app.js` and `dashboard.html`) to interact with it.

---

## Database Design & Row Level Security (RLS)

We track analytical events (like booking creations and cancellations) in a table called `usage_events`. To protect data access while avoiding complex backend authentication, we use Supabase's native **Row Level Security (RLS)**.

### Table: `usage_events`
- `id` (bigint, primary key, auto-incrementing)
- `event_type` (text, not null)
- `created_at` (timestamp with time zone, default: `now()`)

### RLS Policies
1. **Insert Policy (`Allow anon insert`)**:
   - Allows anonymous public users (`anon` role) to insert new usage events.
   - Anyone visiting the booking page can log events.
2. **Select Policy (`Allow anon select with dashboard header`)**:
   - Restricts select permissions to anonymous users who send a custom HTTP header: `x-is-dashboard: true`.
   - The policy inspects the incoming headers via PostgreSQL GUC: `current_setting('request.headers', true)::json->>'x-is-dashboard'`. If it matches `'true'`, access is granted.
   - This ensures that although both the booking site and the dashboard share the same public anon key, only the dashboard can query the event data.

## Step-by-Step Setup Instructions

### 1. Run the SQL Schema in Supabase

1. Go to your [Supabase Dashboard](https://supabase.com/dashboard).
2. Select your project (or create a new one).
3. Click on the **SQL Editor** in the left navigation sidebar.
4. Click **New Query**.
5. Copy and paste the contents of [schema.sql](file:///c:/Users/kimayacolaco/OneDrive%20-%20Microsoft/Vibe%20Coding/mahjong-scheduler/schema.sql):
   ```sql
   -- Create the usage_events table
   CREATE TABLE usage_events (
       id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
       event_type text NOT NULL,
       created_at timestamp with time zone DEFAULT now() NOT NULL
   );

   -- Enable Row Level Security (RLS)
   ALTER TABLE usage_events ENABLE ROW LEVEL SECURITY;

   -- Write an RLS policy for INSERT allowing the public anon role to insert rows
   CREATE POLICY "Allow anon insert" 
   ON usage_events 
   FOR INSERT 
   TO anon 
   WITH CHECK (true);

   -- Write an RLS policy for SELECT allowing the public anon role to read rows 
   -- ONLY if the request contains the header x-is-dashboard equal to 'true'
   CREATE POLICY "Allow anon select with dashboard header" 
   ON usage_events 
   FOR SELECT 
   TO anon 
   USING (
     COALESCE(NULLIF(current_setting('request.headers', true), ''), '{}')::json->>'x-is-dashboard' = 'true'
   );
   ```
6. Click **Run** at the bottom right.

### 2. Configure `app.js` (Event Insertion)

To log events from the client-side booking application, configure the credentials in [app.js](file:///c:/Users/kimayacolaco/OneDrive%20-%20Microsoft/Vibe%20Coding/mahjong-scheduler/app.js). The application uses standard native `fetch` requests directly to the Supabase REST API, keeping the code zero-dependency and lightweight.

1. Open [app.js](file:///c:/Users/kimayacolaco/OneDrive%20-%20Microsoft/Vibe%20Coding/mahjong-scheduler/app.js) and locate the placeholder credentials at the top of the file:
   ```javascript
   const SUPABASE_URL = "YOUR_SUPABASE_URL";
   const SUPABASE_ANON_KEY = "YOUR_SUPABASE_ANON_KEY";
   ```
2. Replace these with your actual Supabase URL and Anonymous Key.
3. The app will now automatically trigger `logUsageEvents` using:
   - `fetch` payload to `/rest/v1/usage_events`.
   - Headers containing the `apikey` and `Authorization: Bearer <key>`.
   - Action triggers placed in `handleNewBooking` (logs `booking_created` for each seat booked) and `handleCancelBooking` (logs `booking_cancelled` for each seat cancelled).

### 3. Configure `dashboard.html` (Event Selection)

The analytics dashboard is a standalone HTML page that does not require any local server or build tool. It also uses a native `fetch` query to read logs.

1. Open [dashboard.html](file:///c:/Users/kimayacolaco/OneDrive%20-%20Microsoft/Vibe%20Coding/mahjong-scheduler/dashboard.html) and locate the placeholder credentials near the bottom of the script section:
   ```javascript
   const SUPABASE_URL = "YOUR_SUPABASE_URL";
   const SUPABASE_ANON_KEY = "YOUR_SUPABASE_ANON_KEY";
   ```
2. Replace these with the same Supabase URL and Anonymous Key.
3. The dashboard makes standard `GET` requests to Supabase with the header:
   ```json
   "x-is-dashboard": "true"
   ```
   This matches the database RLS policy, permitting the dashboard to select and view the analytics logs.
